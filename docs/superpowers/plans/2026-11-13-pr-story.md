# pr-story Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `/dtk:pr-story`, a verified, readable story of what a pull request (or a date range of them) brought in, after moving `action-brief` and its two verification agents into dtk.

**Architecture:** Three PRs in order. PR 1 moves `action-brief`, `claim-verifier` and `link-finder` into the plugin, white-labels them and extends the agents' contract additively. PR 2 adds the `pr-story` skill: a model-driven pipeline (gather → draft → verify → link → deliver) backed by small deterministic scripts for target resolution, the per-user cache and a mechanical format gate. PR 3 adds the digest mode on top of PR 2's cache.

**Tech Stack:** Claude Code plugin (Markdown skills and agents), bash + `jq` scripts under `scripts/pr-story/`, `gh` CLI, offline bash tests with a stub `gh`, paid evals with `claude -p`.

**Spec:** `docs/superpowers/specs/2026-11-13-pr-story-design.md` (landed with this plan in a docs-only PR before PR 1).

## Global Constraints

- Every shipped file (skills, agents, references, examples, evals, fixtures, trigger phrases) is English and white-label: no personal or client names, no private repos, no dependency on a personal skill. Harnu or other environment features are optional only ("when the environment has one").
- Stories are written in English. Another language only when the user's prompt asks for it; the conversation's language alone never switches it.
- GitHub is read through `gh`, authenticated as the running user. No step may rely on unauthenticated `curl` against github.com (private repos answer 404).
- Read-only against GitHub and the target repo. Never posts anywhere. Only the cache files (and, for a viewer, a copy in a git-ignored folder) are written.
- Parallel agents never exceed half the machine's cores.
- Scripts live in `scripts/pr-story/` and are resolved with the idiom in `docs/conventions/script-resolution.md`, pasted verbatim. No skill-local `scripts/` folder.
- Scripts are bash, run on Linux and macOS (no GNU-only flags without a fallback), and need only `bash`, `jq`, `gh`, `git`.
- Cache root: `${XDG_DATA_HOME:-$HOME/.local/share}/dtk/stories/<owner>/<repo>/`.
- Conventional Commits; never edit `CHANGELOG.md` or the plugin version (`.github/workflows/auto-version.yml` does it).
- Each PR is built in a fresh worktree cut from `origin/main`: the local `main` checkout holds unrelated uncommitted changes that must not be touched.

## Review Focus

1. **An open PR that gained commits after its story was cached** must be regenerated, not served stale. Test: Task 5, `status` returns `stale` when the head sha differs.
2. **A PR URL with extra path or fragment** (`/files`, `/commits/<sha>`, `#discussion_r123`, `?w=1`) must resolve to the same PR. Test: Task 5, `story-target.sh` cases.
3. **A bare PR number outside a GitHub checkout** must fail with a clear message, never guess a repo. Test: Task 5, stub `gh repo view` failing → exit 2 with "pass owner/repo#n".
4. **A PR with no description and no review threads** still yields a valid story whose "Left open" reads "Nothing." Test: Task 6, fixture `minimal-pr.md` passes the gate.
5. **A date range with no merged PRs** produces a one-line answer and no digest file. Test: Task 10, `list-merged.sh` returns `[]` and exits 0.

### Task 6: Mechanical story gate

**Files:**
- Create: `scripts/pr-story/check-story.sh`
- Create: `skills/pr-story/tests/fixtures/*.md`
- Modify: `skills/pr-story/tests/run-tests.sh`

**Interfaces:**
- `check-story.sh <file>` → exit 0 when clean; exit 1 printing one `<rule>: <detail>` per violation. (`--digest` is added in Task 11.)
- Rules:
  - `frontmatter`: has `pr: <owner>/<repo>#<n>`, `head_sha:` (40 hex), `lang:`, `generated_at:` (ISO 8601).
  - `title`: exactly one `### ` line; it does not end in `?`, `!` or `…`.
  - `meta`: the first non-empty line after the title starts with `*` and contains `[PR #`.
  - `why`: a line starting `**Why:**`.
  - `sections`: `**What changes for you**` and `**Left open**` both present, in that order, each followed by at least one non-empty line.
  - `unpinned-link`: every `github.com/<o>/<r>/blob/<ref>/` or `/tree/<ref>/` has a 40-hex `<ref>`.
  - `bare-url`: no `http(s)://` outside a Markdown link target.

- [ ] **Step 1: Write fixtures and failing tests.** Fixtures in English about a public PR: `good.md` (all rules pass), `minimal-pr.md` (Left open: `Nothing.`; passes), `no-why.md` → `why`, `hook-title.md` (title ends with `?`) → `title`, `unpinned.md` (`/blob/main/`) → `unpinned-link`, `bare-url.md` → `bare-url`, `sections-swapped.md` → `sections`, `no-frontmatter.md` → `frontmatter`.
